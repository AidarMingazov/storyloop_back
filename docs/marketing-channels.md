# Storyloop — каналы маркетинга

Обновлено: 2026-11-21. **Принято 2026-11-21.** Решения — в `mvp-research.md` (§0), задачи — в `roadmap.md` (волна S).

## Главная идея

**Продукт сам является контентом.** Эпизоды из AI-конвейера (волна 6) — сырьё для роликов.
**Контент-завод — отдельный проект и отдельная область** (с маркетологом), в `storyloop_back` не реализуется.

```
storyloop_back:   AI-конвейер → эпизод в читалке (JSON + медиа в R2)
                                       │
контент-завод:                         └→ ролики 9:16 → TikTok / Reels / Shorts → ссылка с UTM → лендинг или стор
(отдельно)                                     ↑                                                    │
                                        метрики роликов ←──────────────── PostHog / аналитика сторов ┘
```

## Принятые решения

| # | Вопрос | Предложение | Почему |

| M2 | Основной канал | **Контент-завод в коротких видео: TikTok, Instagram Reels, YouTube Shorts** | Формат «вебтун + драма» сам по себе вирусный; стоимость ролика ≈ 0 сверх эпизода |
| M3 | Второй канал | **Сторы (App Store, Google Play) + ASO** | Поиск в сторе — бесплатный поток установок; ключевые слова длинного хвоста, где нет Duolingo |
| M4 | Платный трафик | Только **продвижение лучших органических роликов** (Spark Ads / boost), небольшой бюджет | Не делаем отдельные креативы: завод уже показал, какие ролики работают |
| M5 | «Двигать как ИИ» | **В сторе и рекламе — да** («AI-истории под твой уровень», AI в ключах). **В роликах — нет**: хук = сюжет и язык, не «сделано ИИ». Пометку AI-контента ставим всегда, как требуют платформы | Сюжетный хук смотрят до конца; ролики с явным упором на ИИ аудитория пролистывает |

| M7 | Пейвол в сторах | Приложение в сторе **бесплатное, без кнопки оплаты**. Fake door остаётся только в вебе. In-app покупки — после положительного сигнала | Кнопка «Оплатить», которая не берёт деньги, = риск отказа в ревью Apple |

## 1. Контент-завод (TikTok / Reels / Shorts)

**Формат ролика** (15–45 сек, 1080×1920):
- кадры вебтуна прокручиваются вертикально, пузыри с корейским текстом;
- озвучка реплики (тот же TTS, что в приложении);
- ключевое слово подсвечивается маркером, всплывает перевод и романизация;
- в конце — клиффхэнгер: «Чем закончилось — в приложении / ссылка в профиле».

**Рубрики** (каждая = отдельный аккаунт-ниша, чтобы понять, какая заходит):
1. Мини-дорама сериями: офисный роман, школа, айдол — 1 эпизод = 3–5 частей.
2. «Фраза из K-драмы»: одна реплика, разбор, 3 варианта употребления.
3. «Угадай перевод»: вопрос в первые 2 секунды, ответ в конце.

**Объём:** 3–5 аккаунтов × 1–3 ролика в день. Это 100–300 роликов за 3 недели теста → нужен AI-конвейер, вручную столько не сделать.

**Реализация** — в отдельном проекте завода. Со стороны `storyloop_back` завод получает опубликованные эпизоды (JSON эпизода + медиа); всё остальное — по запросу отдельной задачей.

**Петля «ИИ двигает сам»** (после PoC): метрики роликов (на стороне завода) → какие жанры и хуки выиграли → AI-конвейер генерирует больше таких эпизодов. Это и есть автоматизация каналов вместе с маркетологом.

**Можно начать до кода:** маркетолог заводит и прогревает аккаунты уже в декабре — выкладывает записи экрана читалки с сидовыми эпизодами и проверяет хуки руками.

## 2. Сторы и ASO

**Приложение:** Hotwire Native оболочка iOS + Android (волна S). Чтобы Apple не отклонил как «просто сайт в обёртке» (правило 4.2): нативный таббар, нативная панель слова, push позже.

**Ключевые слова (стартовый набор, проверить в ASO-инструменте):** learn korean, korean webtoon, manhwa, korean stories, k-drama korean, hangul reading, korean comics, AI korean.

**Что настраиваем:**
- iOS: название (30 символов), подзаголовок (30), ключевые слова (100), теги App Store (Apple предлагает их по метаданным, лишние снимаем), подписи на скриншотах;
- **кастомные страницы продукта под ключи** (до 70 на приложение; с июля 2025 участвуют в органическом поиске): отдельная страница под «manhwa», под «k-drama», под «hangul»;
- Google Play: название (30), краткое описание (80), полное описание (4000) — ключи берутся из текста.

**Сроки, которые не зависят от нас:**
- Google Play, **личный** аккаунт: перед публикацией — закрытый тест, 12 тестеров 14 дней подряд. **Аккаунт организации** (нужен D-U-N-S, до ~30 дней) — без этого правила.
- Apple Developer: $99/год, ревью обычно 1–2 дня.
- → Аккаунты разработчика заводим **сейчас** (волна 0), ожидание идёт параллельно с разработкой.

## 3. Аналитика и атрибуция

- Каждый аккаунт и каждый ролик — свой UTM (уже сохраняем в `User.utm`).
- Ссылки и смарт-ссылки (iOS → App Store campaign link, Android → Google Play, десктоп → лендинг) — на стороне завода/маркетолога. Бэкенд только сохраняет UTM на входе.
- PostHog (волна 4) + аналитика сторов. Главные метрики канала: просмотры → переходы → дочитал 1-й эпизод → D1/D7.

## 4. Как это меняет роадмап (применено, детали — в `roadmap.md`)

**Новый порядок:** 1–3 как есть → 4 урезанная → 6 (AI-конвейер, облегчённый) → **S. Сторы** → тест спроса. Контент-завод — параллельно, отдельным проектом.

| Волна | Что | Дни (оценка) |
|---|---|---|
| 1–3 | как в роадмапе | 15 |
| 4 урезанная | гость, онбординг, fake door, лендинг ko-en, PostHog, деплой. Без magic link и PWA | ≈ 7 |
| 6 облегчённая | сценарий, картинки, разметка, озвучка, review. Сравнение провайдеров — минимальное | ≈ 10 |
| **S. Сторы** | Hotwire Native iOS + Android, нативный таббар, без пейвола, ASO-метаданные | ≈ 6 + ревью |

**Выкидываем из PoC:** manga и illustrated (5.1, 5.2), JSON API (5.4 — Hotwire Native его не требует), Stripe (7.2), email-напоминания (7.3), PWA (4.9), magic link (4.4).

**Ориентир:** веб готов к трафику с завода с ~12 января; сторы — начало февраля (с учётом 14 дней теста Google Play при личном аккаунте).
