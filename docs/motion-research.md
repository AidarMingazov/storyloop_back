# Motion Story Engine — техническое видение

Обновлено: 2026-11-21. Статус: исследование, **не план волны**. Источник — ТЗ «Motion Story Engine» (анимированные комиксы для изучения языка) и текущий код `main` + перевод 7.8 из ветки волны 7.

Коротко: анимацию можно сделать почти без новых сущностей. Сцена — это кадр (`Panel`). Конфиг движения хранится в `panels.motion jsonb` и ссылается только на позиции и ключи, а не на id, поэтому переводы эпизода (7.8) получают его копированием вместе с общими картинками. Плеер — ещё один рендерер в `reader/`, на WAAPI + Canvas 2D + CSS, без новых JS-библиотек.

---

## 1. Что уже есть и как это ложится на ТЗ

| ТЗ | В коде сейчас | Комментарий |
|---|---|---|
| Story | `Series` + `Episode` | серия привязана к `LanguagePair` |
| Scene | `Panel` | одна картинка = одна сцена Motion-режима |
| Panel | `Panel` | — |
| Character | `Character` (на серию) | есть `avatar`, `sheet`, `voice` |
| Dialogue | `Bubble` (speech / thought / narration / chat_message) | `box` в процентах картинки |
| StoryVersion | эпизод-перевод: `origin_episode_id` (7.8) | копия эпизода в другой паре |
| LocalizedDialogue | `Bubble` эпизода-перевода с той же `position` | + `Token`, `translation` |
| AudioAsset | `Bubble.audio`, `Lexeme.audio` (ActiveStorage) | MiniMax отдаёт `audio_length`, но он не сохраняется |
| VisualAsset | blobs ActiveStorage (`Panel.image`, `Character.sheet/avatar`) | blobs уже переиспользуются между переводами |
| AnimationPreset / SceneAnimation / AnimationLayer / SceneAudio / StoryChoice | нет | см. §3 |

Что важно для архитектуры:

- **Многоязычность уже решена копированием.** `Stories::Translation` (7.8) создаёт копию эпизода, где кадров столько же, пузырей в каждом кадре столько же и в тех же позициях, а картинки — те же blobs. Заново делаются только текст, разметка и озвучка. Поэтому требование «анимация не зависит от языка» выполняется одним правилом: **конфиг движения ссылается на `panel.position`, `bubble.position`, `character.key` и ключи ассетов, но никогда на id.** Тогда его можно копировать в перевод так же, как `layout`.
- **Стек: Rails 8.1 + Stimulus + importmap, без сборщика и без React.** Ридер — это ванильные модули `app/javascript/reader/*` и `reader_controller`. WAAPI (`element.animate`) уже используется. Есть свой `Pager` с эффектами slide/curl/fade и есть `prefersReducedMotion()`. Framer Motion и GSAP здесь не нужны: WAAPI умеет всё, что нужно таймлайну (`pause`, `play`, `currentTime`, `playbackRate`).
- **Идея уже лежит в роадмапе** («После PoC»: `Panel.motion jsonb`, пресеты, появление пузырей синхронно с озвучкой, параллакс по слоям). Это видение её развивает.

## 2. Главные решения (и где я расхожусь с ТЗ)

1. **Сцена = кадр.** В Motion-режиме экран показывает один кадр. Переходы между кадрами делает уже готовый `Pager`. Новая сущность Scene не нужна.
2. **Не 6 новых таблиц, а `panels.motion jsonb` + пресеты в YAML + одна таблица библиотеки звуков.** Конфиг всегда читается целиком вместе с кадром, по его полям ничего не ищут, он копируется при переводе и проверяется JSON Schema (`json_schemer` уже есть, так же сделан `config/schemas/episode.json`). Таблицы SceneAnimation/AnimationLayer дали бы 5+ join на кадр и усложнили бы копию перевода, ничего не дав взамен.
3. **Пресеты раскрываются на сервере, клиент знает только примитивы.** `Motion::Config` превращает `{"camera": {"preset": "slow_zoom_in"}}` в конкретные `{type: "zoom", from: 1, to: 1.1, …}` и подставляет значения по умолчанию. В JS есть только реестр примитивов (zoom, pan, rain, fade…). Пресеты меняются без деплоя JS, а будущий нативный клиент из API v1 получает уже готовый конфиг.
4. **Тайминг реплик относительный, без абсолютных миллисекунд.** Корейская и английская реплики звучат разное время. Поэтому в конфиге задаются порядок, паузы и способ появления, а длительность считается в рантайме: по длине озвучки или по времени чтения для языка и уровня. Абсолютное время есть только у камеры, эффектов и появления персонажей.
5. **Выбор — это пузырь `kind: "choice"` со структурным полем `goto`.** Текст выбора локализуется, размечается токенами (слова в выборах можно тапать) и озвучивается тем же конвейером. В переводе пузырь копируется вместе с `goto` и ничего ломать не надо.
6. **Параллакс в MVP строится из процедурных слоёв.** Кадр под камерой, частицы и туман на разных скоростях, блок реплик — это 3–4 плоскости с разной скоростью без единой новой картинки. Настоящие слои (карта глубины или вырезки) — во второй очереди, см. §3.4.
7. **Персонажи двигаются как портреты в духе визуальной новеллы, а не внутри картинки.** Персонаж «запечён» в кадр, поэтому fade-in, «дыхание» и смену спрайта без слоёв на нём не сделать. Зато портрет говорящего у блока реплики (`Character.avatar`, позже набор эмоций) даёт всё это дёшево: спрайты генерируются один раз на персонажа и годятся для всех эпизодов и языков.
8. **Реплики в Motion-режиме идут блоком под кадром.** Кадр 4:5 на портретном экране телефона оставляет снизу место. Блок не обрезается камерой, не зависит от длины текста на конкретном языке и даёт крупный текст для учёбы. Пузыри на картинке остаются опцией (`dialogue.style: "bubbles"`) для webtoon/manga, где `box` уже подогнан шагом Layout.

## 3. Данные

### 3.0 `panels.scene` — факты о кадре (сделано, M.α)

Конвейер уже пишет закрытые теги кадра (`config/schemas/scene.json`, `Ai::Steps::Scene`, `PanelScene`):

```json
{ "v": 1, "setting": "interior", "place": "home", "time": "night", "weather": "clear", "light": "neon",
  "mood": "calm", "shot": "medium", "focus": "jisoo", "elements": ["city_lights", "steam"] }
```

Это описание того, что нарисовано, а не команды анимации. `panels.motion` (ниже) хранит только ручные правки. Порядок такой: сначала значения по умолчанию, поверх них правила по тегам `scene`, поверх правил ручной `motion`. Поэтому смена пресетов и правил никогда не требует новой генерации. Первый живой прогон (seoul-starter №1, Haiku 5.5): 10 кадров за 7.7 с, $0.0011, все теги прошли проверку с первой попытки.

### 3.1 `panels.motion` (jsonb, по умолчанию `{}`)

Так хранится (это пишет человек или AI):

```json
{
  "v": 1,
  "camera":   { "preset": "slow_zoom_in", "focus": { "x": 62, "y": 38 } },
  "effects":  [ { "preset": "rain", "area": { "x": 0, "y": 0, "w": 40, "h": 55 }, "intensity": 0.7 },
                { "preset": "warm_glow", "at": { "x": 70, "y": 20 } } ],
  "cast":     [ { "character": "mia", "enter": "fade_in", "idle": "breathe" } ],
  "dialogue": { "style": "box", "start": 1200, "reveal": "typewriter", "gap": 500 },
  "bubbles":  { "2": { "reveal": "pop", "delay": 300 } },
  "audio":    { "ambient": "cafe_rain", "music": "calm_evening" },
  "transition": { "preset": "crossfade" }
}
```

Так выглядит в `EpisodePayload` после `Motion::Config.resolve(panel)`:

```json
"motion": {
  "v": 1,
  "camera":  [ { "type": "zoom", "from": 1, "to": 1.1, "origin": [62, 38], "duration": "scene", "easing": "ease-in-out" } ],
  "effects": [ { "type": "rain", "density": 0.7, "angle": 12, "speed": 1, "area": [0, 0, 40, 55] },
               { "type": "glow", "at": [70, 20], "color": "warm", "period": 4000 } ],
  "dialogue": { "style": "box", "start": 1200, "gap": 500, "reveal": "typewriter", "cps": 9 },
  "audio":   { "ambient": { "url": "…", "volume": 0.5 }, "music": { "url": "…", "volume": 0.3 } },
  "transition": { "type": "fade", "duration": 600 }
}
```

Правила:

- Координаты в процентах картинки, как в `Bubble#box`.
- Пустой `motion` превращается в разумные значения по умолчанию: лёгкий наезд в центр, реплики по очереди, переход fade. Значит, **любой существующий эпизод сразу можно смотреть в Motion-режиме.**
- В конфиге нет URL, только ключи ассетов. Сервер сам превращает их в ссылки на blobs, поэтому конфиг не может сослаться на чужой ресурс.
- `v` — версия схемы. `Motion::Config` обновляет старые версии. Клиент молча пропускает неизвестные поля и типы.

### 3.2 Проверка

- `config/schemas/motion.json`: `additionalProperties: false`, перечисления для всех `preset`/`type`/`reveal`/`easing`, диапазоны (zoom 1–1.3, длительности 200–30000 мс, density 0–1, проценты 0–100).
- `Panel validate :motion_matches_schema`. Это тот же приём, что `Bubble#box_is_percent_rect` и проверка эпизода.
- `Motion::Config`:
  - `validate(hash)` возвращает список ошибок, которые AI-шаг отдаёт модели на повтор (как в `Ai::ScriptCheck`);
  - `resolve(panel)` раскрывает пресеты и подставляет значения по умолчанию;
  - `upgrade(hash)` обновляет версию.
- Ни один JS из конфига не исполняется: клиент сопоставляет строку типа с функцией из своего реестра.

### 3.3 Пресеты — `config/motion/presets.yml`

```yaml
camera:
  still:          []
  slow_zoom_in:   [{ type: zoom, from: 1.0, to: 1.10, duration: scene, easing: ease-in-out }]
  slow_zoom_out:  [{ type: zoom, from: 1.12, to: 1.0, duration: scene, easing: ease-out }]
  cinematic_pan:  [{ type: pan, from: left, to: right, zoom: 1.12, duration: scene, easing: linear }]
  ken_burns:      [{ type: kenburns, from: [0, 0, 100, 100], to: [10, 8, 82, 82], duration: scene }]
effects:
  rain:       { type: rain, density: 0.6, angle: 12, speed: 1.0 }
  heavy_rain: { type: rain, density: 1.0, angle: 18, speed: 1.4 }
  snowfall:   { type: snow, density: 0.5, drift: 0.4 }
  dust:       { type: particles, density: 0.3, glow: true }
  fog:        { type: fog, opacity: 0.35, speed: 0.2 }
  light_rays: { type: rays, opacity: 0.25 }
  warm_glow:  { type: glow, color: warm, period: 4000 }
transitions:  { crossfade: { type: fade, duration: 600 }, slide: { type: slide }, zoom: { type: zoom, duration: 700 }, cut: { type: none } }
scenes:       # готовые наборы, которые AI выбирает целиком
  rainy_evening: { camera: slow_zoom_in, effects: [rain, warm_glow], ambient: rain_window }
  snowy_street:  { camera: cinematic_pan, effects: [snowfall], ambient: winter_street }
```

YAML лежит в git: пресеты версионируются вместе с кодом, а их список попадает в `enum` схемы и в промпт AI. Таблицу для пресетов стоит заводить, только если понадобится править их из админки без деплоя.

### 3.4 Ассеты

| Что | Где хранить | Когда |
|---|---|---|
| Картинка кадра | уже есть (`Panel.image`); добавить вариант `:motion` 1600w, иначе на зуме 1.1 будет мыло | MVP |
| Длительность озвучки | `audio_ms` в `metadata` блоба `Bubble.audio` (MiniMax уже его возвращает) | MVP |
| Фоновые звуки и музыка | таблица `sound_assets` (`key`, `kind: ambient/music/sfx`, файл, `loop`, `volume`, `license`); 15–20 CC0-лупов в m4a, моно, 64 kbps | MVP |
| Портреты/эмоции персонажа | `Character has_many_attached :expressions` (в metadata ключ эмоции); 4–6 эмоций ≈ $0.2 на персонажа один раз | 2-я очередь |
| Карта глубины кадра | `Panel has_one_attached :depth_map` (Depth Anything через Replicate/fal ≈ $0.002 за кадр) → 2.5D-параллакс в WebGL | 2-я очередь |
| Слои-вырезки | `Panel has_many_attached :layers` (вырезка персонажа + фон без него через inpaint ≈ $0.04 за кадр) | только если карта глубины не понравится |

Почему для параллакса первой идёт карта глубины: из одного плоского кадра она даёт настоящую глубину одним дополнительным файлом и одним шейдером. При малых смещениях на краях нет «призрака» персонажа. С вырезками без inpaint персонаж двоится, а с inpaint кадр становится заметно дороже.

### 3.5 Выборы и ветвление

- `bubbles.kind` получает значение `choice`, плюс колонка `bubbles.goto` (integer): позиция кадра, куда ведёт выбор.
- `panels.layout["next"]`: куда идти после кадра, если это не `position + 1`. Так ветки снова сходятся.
- `reading_progresses.path` (jsonb): какие выборы сделаны. Без этого не восстановить место чтения в ветвящемся эпизоде.
- В режиме чтения выбор — это кнопки, и показываются только кадры выбранной ветки. В Motion-режиме выбор работает как барьер таймлайна (§4.2).
- `conditions` из ТЗ закладываем в схему как зарезервированное поле, но не реализуем.
- Отдельный вопрос — генерация ветвящихся сценариев AI. Шаг «Сценарий» и `ScriptCheck` сейчас линейные. Для начала хватит шаблона «одна развилка на эпизод, 2–3 варианта, каждый на 1–2 кадра, потом слияние». Ветки, написанные руками в сидах и импорте, работают сразу.

### 3.6 Перевод (7.8)

`Stories::Translation` уже копирует `layout`. Нужно добавить копирование `motion`, `bubbles.goto` и `kind: choice`, а у `ScriptCheck` — проверку, что выборы стоят на тех же местах. Картинки, карты глубины и вырезки — общие blobs, их ничего не генерирует заново. Если правка движения в оригинале должна доезжать до переводов, есть два варианта. Первый: кнопка «Синхронизировать движение» в админке. Второй: payload перевода берёт `motion` у кадра с той же позицией в `origin_episode` (без N+1, одним запросом). Предлагаю начать с копирования.

## 4. Плеер (фронт)

### 4.1 Модули

```
reader_controller.js         режим, панель слова, сохранение слов, прогресс — уже есть
└── reader/motion/player.js  MotionStoryPlayer: сцены по пути, режим реплик, контролы, предзагрузка
    ├── reader/pager.js      переходы между сценами: fade/slide уже есть, добавить drawZoom
    ├── motion/scene.js      SceneRenderer: DOM кадра, порядок слоёв, ресайз
    │   ├── motion/camera.js    CameraController: zoom/pan/kenburns → ключевые кадры WAAPI (только transform)
    │   ├── motion/effects.js   EffectsLayer: canvas для дождя, снега и частиц; CSS для тумана, лучей и свечения
    │   └── motion/cast.js      портреты говорящих: появление, «дыхание», смена
    ├── motion/dialogue.js   DialogueRenderer + SubtitleController: tokenizedText(), появление, is-speaking, ⇄ перевод
    ├── motion/timeline.js   Timeline: часы, события (cue), барьеры, pause/resume, playbackRate
    ├── motion/audio.js      AudioController: AudioContext, шины music/ambient/voice, приглушение, разблокировка
    └── motion/choices.js    кнопки выбора, путь
```

Отдельный LearningInteractionLayer не нужен. Текст реплики рендерится тем же `tokenizedText(bubble)` с теми же `data-token-id`, поэтому `stageClick`, `WordSheet` и сохранение слов работают как есть.

Раскладка экрана в Motion-режиме: сверху контролы (⏯, режим реплик, звук), в центре кадр 4:5 (камера, эффекты, опционально пузыри), снизу блок реплики (портрет, имя, текст с токенами, 🔊 ⇄, кнопки выбора). На десктопе всё это стоит колонкой по центру.

### 4.2 Таймлайн: один движок, три режима реплик

Сцена собирает дорожки:

```
camera:   0 → sceneEnd       duration "scene" растягивается под фактическую длину сцены
effects:  0 → ∞              бесконечный цикл, ставится на паузу вместе со сценой
cast:     появление в момент t (мс)
dialogue: show_i = end_{i-1} + gap
          hold_i = audio ? audio_ms_i : max(minHold, chars_i / cps(lang, cefr))
          после каждой реплики — барьер
choices:  барьер «ждём выбор»
sceneEnd = max(camera.min, dialogue.end + tail)
```

Режимы ТЗ (manual / automatic / audio-driven) отличаются только **типом барьера** после реплики: тап, таймер или событие `ended` у озвучки. Пока стоит барьер, часы стоят, а эффекты продолжают идти. Пауза ставит на паузу WAAPI-анимации (`getAnimations()`), canvas-цикл и аудио. Продолжение запускает их снова.

Правила, чтобы анимация не мешала учёбе:

- Тап по слову в любой момент открывает панель слова и ставит таймлайн на паузу. Закрыли панель — воспроизведение продолжается (это настройка).
- Тап по реплике, которая ещё печатается, сразу показывает её целиком.
- «Печатная машинка» открывает текст **по токенам** (opacity у span), а не по буквам. Так она одинаково работает для корейского, японского и английского, и открытые слова сразу можно тапать.
- Подсветка `is-speaking` во время озвучки работает на уровне реплики. Подсветка по словам (караоке) — не в MVP.

### 4.3 Камера, эффекты, персонажи

- **Камера**: обёртка `.motion-camera` с `transform-origin` в точке фокуса. Анимируются только `scale` и `translate` через WAAPI. `will-change: transform` включается на время анимации и потом снимается.
- **Дождь, снег, частицы**: один `<canvas>` на сцену, DPR не выше 1.5. Число частиц = плотность × площадь × уровень качества. Эффект можно обрезать прямоугольником `area` («дождь только за окном»). Цикл `requestAnimationFrame` работает только у видимой сцены, на открытой вкладке и без паузы.
- **Туман, лучи, свечение**: заранее размытые градиенты (CSS), у которых анимируются только `transform` и `opacity`. `filter: blur()` не анимируем.
- **Персонажи**: портреты в блоке реплики (fade/slide при входе, «дыхание» — `scale` 1↔1.015 за 4 с, смена портрета при смене говорящего). Движение внутри кадра — только со слоями или картой глубины, во второй очереди.
- **Переходы**: через `Pager`: `fade` (crossfade), `slide`, новый `zoom`. Свайп и тап по краям работают уже сейчас.

### 4.4 Аудио

- Одна `AudioContext` создаётся по первому жесту: кнопка «▶ Смотреть» снимает ограничение автозапуска.
- Шины `music`, `ambient` и `voice` (GainNode) сводятся в master. Лупы идут через `createMediaElementSource`, то есть стримятся без полного декодирования.
- **На iOS `HTMLMediaElement.volume` только для чтения**, поэтому громкость и приглушение делаем только через GainNode. Пока звучит голос, музыка опускается до 0.35 за 200 мс.
- Если у соседних сцен один и тот же ambient, он играет дальше, иначе звуки плавно сменяют друг друга. На `visibilitychange` всё ставится на паузу. В настройках — громкость музыки, фона и голоса.
- `speech.js` (озвучка слова в панели) идёт через ту же шину `voice`, чтобы голоса не накладывались.
- В Hotwire Native (волна S) нативная оболочка может разрешить автозапуск (`mediaTypesRequiringUserActionForPlayback`).

### 4.5 Режимы и деградация

- Переключатель «Режим: Чтение / Движение» в настройках ридера (`writeChoice`, как у `page_turn`), плюс `?mode=motion`. Доступен для webtoon, manga и illustrated. Для chat режима движения нет.
- В режиме чтения `motion` игнорируется, а рендереры работают без изменений. Добавляются только кнопки выбора для ветвящихся эпизодов.
- Уровни качества:
  - `off` при `prefers-reduced-motion`: камера стоит, частиц нет, реплики появляются через fade;
  - `low` при `saveData`, `deviceMemory ≤ 3` или `hardwareConcurrency ≤ 4`: частиц в 2.5 раза меньше, 30 fps, без WebGL;
  - `high` во всех остальных случаях.
  
  Сторож FPS понижает уровень, если средний кадр дольше 24 мс в течение 2 секунд.
- Предзагрузка: картинка следующей сцены (`img.decode()`) и озвучка её первой реплики. Не дальше одной сцены вперёд. При `saveData` — без предзагрузки и без фоновых звуков по умолчанию.
- Прогресс: плеер вызывает тот же `reached(panel.position)`, поэтому модель прогресса не меняется (плюс `path` для веток).

## 5. AI-шаг «Движение»

> Обновление 2026-11-21: вместо LLM-шага, который выбирает пресеты, сделан шаг «Сцена» (§3.0). Он пишет факты о кадре, а движение из них строят правила в коде. Ниже — первоначальный вариант, оставлен для истории.

- Место в конвейере: `STEPS = %w[script images layout motion tokens audio]`. В `THEN["script"]` добавляется `motion`, в админке появляется «перезапустить шаг». В переводе шаг **не запускается**: конфиг копируется.
- На входе по каждому кадру: `image_prompt` (описание сцены), количество и тип реплик, кто говорит, жанр и тон серии, а также перечисления пресетов и ключей звуков. Все кадры уходят одним запросом. Модель — дешёвая (`deepseek-flash` / `haiku`), JSON на выходе.
- На выходе по каждому кадру: `{camera, effects, audio, transition, dialogue.reveal}` только из перечислений.
- Проверка через `Motion::Config.validate`, при ошибках — до 2 повторов с их списком (приём из `ScriptCheck`). Если не вышло, берутся значения по умолчанию из `Motion::Defaults`. **Конвейер никогда не падает из-за движения.**
- Точки фокуса (лицо, окно для дождя) во второй очереди можно получить vision-моделью (`gemini-flash` уже настроен как `vision`, ≈ $0.0005 за кадр). В MVP хватит пресетов, которым фокус не нужен.
- Стоимость: ≈ $0.001–0.003 за эпизод. Это меньше процента от стоимости картинок (Seedream ≈ $0.04 × 8–12 кадров).

Админка на экране проверки эпизода: у каждого кадра выпадающие списки (камера, эффект, звук), кнопка «▶ превью» (тот же плеер в модалке), JSON-поле с ошибками схемы и кнопка «Синхронизировать движение в переводы».

## 6. Производительность и стоимость

- Видео не генерируется. Новые файлы — только библиотека звуков (один раз), а во второй очереди карты глубины (≈ $0.002 за кадр) и эмоции персонажей (≈ $0.2 на персонажа один раз). Для каждого языка генерируется только то, что уже генерируется сейчас: текст, разметка и озвучка.
- Анимируются только `transform` и `opacity`, и только у текущей сцены. Canvas останавливается вне экрана и на фоне.
- Вес payload: `motion` ≈ 0.5–1 КБ на кадр, то есть порядка 10 КБ на эпизод.

## 7. Тесты

- Unit: `Motion::Config` (значения по умолчанию, раскрытие пресетов, отказ на неизвестный тип и на URL, обновление версии), валидация `Panel`, `Ai::Steps::Motion` с fake-LLM (валидный ответ / невалидный → повтор → значения по умолчанию), `Stories::Translation` копирует `motion` и `goto`, blobs не дублируются, `EpisodePayload` отдаёт раскрытый `motion` и `audio_ms`.
- Системные (Capybara/Selenium, как сейчас):
  - переключение режима сохраняется;
  - пауза и продолжение (состояние в `data-motion-state`);
  - тап по слову во время воспроизведения открывает панель и ставит паузу;
  - выбор ведёт на нужный кадр;
  - reduced motion (Chrome с флагом `--force-prefers-reduced-motion`);
  - ширина 375×812.
- Чтобы тесты были детерминированными: `?motion_rate=20` ускоряет часы таймлайна и `playbackRate` у WAAPI.

## 9. Риски и открытые вопросы

1. **Помогает ли движение учёбе или мешает?** Анимация замедляет чтение. Нужен A/B: Motion по умолчанию включён или выключен. Метрики — дочитывание, тапы по словам за эпизод, D7. Ради этого и нужен M.0.
2. **Реплики: блок под кадром или пузыри на картинке.** Я за блок (не зависит от языка и не обрезается камерой), пузыри — опция.
3. **Выборы в этом объёме или отдельно.** Ветвящиеся сценарии — это отдельная продуктовая фича, которая затрагивает «Сценарий», `ScriptCheck` и перевод. Её можно вынести.
4. **iOS:** громкость только через Web Audio. Тихий режим глушит Web Audio (`navigator.audioSession.type = "playback"` в новых Safari). Это нужно проверить на устройстве.
5. **Слабые Android:** нагрев и батарея от canvas. Защищают уровни качества и сторож FPS.
6. **Лицензии звуков:** только CC0 или аналог. Источник и лицензию храним в `sound_assets.license`.
